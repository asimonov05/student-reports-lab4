ТЗ на лабораторную работу № 4
1. Задача
Разработать программу для Linux, которая анализирует посещаемость и результаты тестирования студентов. Исходные данные — файловая система преподавателя из лабораторной работы № 3.
Реализовать все пять функций, перечисленных ниже. Первые две относятся к базовой части задания, остальные три — к дополнительной части для получения отличной оценки.
2. Технические требования
Вся логика программы реализуется на Bash с использованием команд и утилит Linux.
Сторонние скрипты, например Python, не используются.
Дополнительных ограничений на команды и утилиты нет.
Структура и форматы исходных файлов берутся из лабораторной работы № 3. Программа не изменяет исходные данные.
Для пользователя реализуется графический интерфейс на русском языке.
Результаты обработки формируются как текст в стандартном потоке вывода и отображаются в графическом окне.
Отдельная функция сохранения результатов в файл не требуется.
3. Функции
В рамках одного года конкретный тест однозначно определяется названием предмета и номером теста. Если функция работает с конкретным тестом, пользователь задаёт оба параметра. В функции 2 данные рассматриваются без фильтра по годам, в функции 5 — отдельно за каждый год.
3.1. вывод списка студентов заданной группы с наилучшей посещаемостью за заданный период (например, c 4го по 10ое занятие)
Вывести список студентов заданной группы с наилучшей посещаемостью по выбранному предмету за заданный период, например с 4-го по 10-е занятие.
Пользователь задаёт:
номер группы;
предмет;
номер первого и последнего занятия.
Программа определяет лучшую посещаемость за указанный диапазон и выводит всех студентов с одинаковым максимальным значением.
Программа выводит:
ФИО всех студентов с наилучшей посещаемостью;
количество посещённых занятий за выбранный период для каждого студента.
Границы диапазона включаются.
3.2. вывод имени студента, с максимальным количеством пересдач теста с указанием их количества
По заданным пользователем номеру группы, предмету и номеру теста вывести имя студента с максимальным количеством пересдач указанного теста по выбранному предмету и указать их количество.
Пользователь задаёт:
номер группы;
предмет;
номер теста.
Программа выводит:
имя студента с максимальным количеством пересдач;
количество пересдач.
Данные учитываются без дополнительного фильтра по годам. Если максимальное количество пересдач одинаково у нескольких студентов, вывести одного любого.
3.3. вывод списка студентов, сдавших все тесты с первой попытки
Вывести список студентов, сдавших все тесты одного выбранного предмета с первой попытки.
Пользователь задаёт:
предмет.
Программа выводит:
ФИО всех студентов, сдавших все тесты выбранного предмета с первой попытки.
3.4. вывод студентов с самыми длинными фамилиями
Найти студентов с максимальной длиной фамилии по всей базе, без ограничений по группам, предметам и годам.
Пользователь задаёт:
параметры не требуются.
Программа выводит:
ФИО всех студентов с фамилией максимальной длины;
длину фамилии в символах.
Длина определяется количеством символов в фамилии, а не байтов.
3.5. вывод студентов с наилучшими результатами (по количеству правильных ответов) за каждый год сдачи теста
Вывести студентов с наилучшими результатами по количеству правильных ответов за каждый год сдачи конкретного теста, заданного названием предмета и номером.
Результаты сгруппировать по годам. Для каждого года вывести всех студентов с одинаковым максимальным значением.
Пользователь задаёт:
название предмета;
номер теста.
Программа выводит:
год сдачи теста;
ФИО всех студентов с максимальным результатом за этот год;
количество правильных ответов.
4. Графический интерфейс
Средство реализации
Есть предложение использовать Zenity — утилиту для создания графических диалоговых окон из shell-скриптов. Bash вызывает окна, получает выбранные значения, выполняет обработку данных и передаёт результат в окно вывода.
Таким образом, интерфейс состоит из обычных графических окон, а логика остаётся в Bash. Для запуска нужны установленная Zenity и графическая сессия Linux.
Справка для разработчика: документация Zenity в репозитории GNOME.
Главное окно
Название: «Анализ данных студентов».
В окне отображается список из пяти функций:
1. Вывод списка студентов заданной группы с наилучшей посещаемостью за заданный период;
2. Вывод имени студента, с максимальным количеством пересдач теста с указанием их количества;
3. Вывод списка студентов, сдавших все тесты с первой попытки;
4. Вывод студентов с самыми длинными фамилиями;
5. Вывод студентов с наилучшими результатами за каждый год сдачи теста.
Пользователь выбирает функцию и нажимает «Открыть». Кнопка «Выход» завершает программу.
Ввод параметров
Для функции 1: выбор группы, выбор предмета, ввод начального и конечного номера занятия.
Для функции 2: выбор группы, предмета и номера теста.
Для функции 3: выбор предмета.
Для функции 4: запуск обработки после выбора функции.
Для функции 5: выбор предмета и номера теста.
Группы и предметы выбирать из списков, сформированных по исходным данным. Номера занятий вводить в подписанные поля.
В функциях 2 и 5 сначала выбрать предмет, затем номер теста из доступных по этому предмету. Один и тот же номер у разных предметов обозначает разные тесты.
Допускается последовательность нескольких диалоговых окон. Собирать все элементы в одном окне не требуется.
Кнопка «Отмена» прерывает текущую операцию и возвращает пользователя в главное меню. Отмена не считается ошибкой.
Окно результата
В заголовке указать название выполненной функции.
Перед результатом показать заданные пользователем параметры, если они есть.
Результат представить таблицей или читаемым текстовым списком.
Для длинных списков предусмотреть прокрутку.
После закрытия результата вернуть пользователя в главное меню.
Если подходящих студентов нет, вывести понятное сообщение об отсутствии результатов.
Проверка ввода и сообщения
Перед обработкой проверить заполнение обязательных полей и корректность диапазона занятий: номера — положительные целые числа, начало не больше конца.
При неверном вводе показать сообщение с объяснением и дать повторить ввод. Если исходные файлы отсутствуют, недоступны или не могут быть прочитаны в ожидаемом формате, сообщить об этом пользователю.
При отсутствии Zenity вывести в терминал сообщение о необходимой зависимости.
