# Требования и правила обработки данных

Решение реализует индивидуальное [ТЗ](source/ТЗлаб4.docx) на основе [общего задания ЛР № 4](https://github.com/dmieter/os-labs/blob/e52e240/labs-2026/lab-4/README.md). Уточнения преподавателя из переписки 22–24 октября 2026 года задают области поиска и правила обработки равных максимумов. Технические и интерфейсные требования берутся из ТЗ: Linux, Bash и команды Linux, русский графический интерфейс, текстовый стандартный вывод, неизменность исходных данных.

В текущей версии оставлен только командный интерфейс. Графический интерфейс удалён; соответствующее требование исходного ТЗ не реализовано. Исходное ТЗ сохранено без изменений.

Ограничение на awk из ЛР № 3 на эту работу не переносится: преподаватель отдельно разрешил команды Bash без дополнительных ограничений. Python и другие сторонние скриптовые среды для работы программы не используются.

## Функции

| Функция | Параметры | Область анализа | Результат |
| --- | --- | --- | --- |
| Посещаемость | Группа, предмет, первое и последнее занятие | Выбранные группа и предмет; обе границы включены | Все студенты с максимальным числом посещений и это число |
| Пересдачи | Группа, предмет, номер теста | Выбранные группа и тест, все даты | Один студент с максимальным числом пересдач и это число |
| Все тесты с первой попытки | Предмет | Все группы выбранного предмета | Все студенты, сдавшие каждый из четырёх тестов без пересдач |
| Длина фамилии | Нет | Вся база, без фильтров | Все студенты с максимальной длиной фамилии и длина в символах |
| Лучшие результаты по годам | Предмет, номер теста | Все группы выбранного теста | Для каждого года все студенты с максимальным числом правильных ответов |

У функций 3–5 нет неявного ограничения по группе. В функции пересдач преподаватель разрешил одного любого победителя при равенстве; программа выбирает одного в стабильном алфавитном порядке. В остальных функциях возвращаются все равные максимумы.

## Формат базы

Исходные файлы взяты из [архива ЛР № 3](https://github.com/dmieter/os-labs/blob/e52e240/labs-2026/lab3/labfiles-3-26.zip). Включённая база содержит 30 групп, 463 пары «группа и студент», два предмета по четыре теста, 7 431 попытку за 2007–2026 годы. Это исходная учебная база, без индивидуальных правок из отчёта ЛР № 3.

```text
labfiles-3-26/
├── students/
│   ├── groups/<группа>
│   └── general/notes/...
└── <предмет>/
    ├── <группа>-attendance
    └── tests/
        ├── TEST-1
        ├── TEST-2
        ├── TEST-3
        └── TEST-4
```

В списке группы каждый непустой ряд содержит идентификатор студента. Идентичность студента определяется парой «полное обозначение группы, идентификатор»; одинаковое имя в разных группах не означает одного человека. Полных ФИО в базе нет, поэтому программа не пытается их восстанавливать.

Строка посещаемости содержит идентификатор, пробел и последовательность `0` и `1`: `1` означает посещение, `0` — пропуск. Позиции считаются от единицы. В поставляемой базе на студента приходится 18 отметок. Диапазон за пределами имеющихся отметок считается некорректным, а не отсутствием посещений.

Каждая строка `TEST-N` — отдельная попытка с пятью полями через точку с запятой:

```text
A-06-04;YemelyanovD;2007-10-25;7;2
```

Поля: группа, идентификатор студента, дата `ГГГГ-ММ-ДД`, число правильных ответов, оценка. Номер теста всегда рассматривается вместе с предметом. Заметки преподавателя в `students/general/notes` для расчётов не требуются.

## Принятые определения

Эти правила уточняют неоднозначности исходного задания; они не выдаются за дополнительные ответы преподавателя.

- **Пересдача** — любая попытка после первой: `max(число попыток − 1, 0)`. Считаются все строки выбранного теста для студента без фильтра по году; положительная оценка не исключает строку из подсчёта.
- **Сдал с первой попытки** — у студента ровно одна запись в каждом из четырёх тестов предмета, и каждая оценка не ниже 3. В ЛР № 3 указано, что попытки продолжаются до первой удовлетворительной оценки. Даты в учебной базе не упорядочены по последовательности попыток, поэтому сортировка по дате не определяет первую попытку надёжно. Студент с пропущенным тестом или дополнительной попыткой в список не попадает.
- **Удовлетворительная оценка** определяется числовой частью. Например, `3--`, `4+` и `5++` считаются успешными оценками; суффикс не меняет порог.
- **Фамилия** выделяется как начальная часть идентификатора из слова с заглавной буквы и последующих строчных букв; части двойной фамилии соединены дефисом. Остаток считается инициалами. Например, `YemelyanovD` даёт `Yemelyanov`, `KhizhniakovVlS` — `Khizhniakov`, `Surovtsev-ButovA` — `Surovtsev-Butov`. Используются классы символов Unicode в локали UTF-8; дефис входит в длину фамилии. Это соглашение о формате учебной базы, а не универсальный разбор человеческих имён.
- **Лучший результат года** — максимальное число правильных ответов в одной попытке выбранного теста. Год берётся из даты попытки. Результаты не суммируются; студент с несколькими равными лучшими попытками выводится один раз за год.

## Проверки и интерфейс

Командный интерфейс предоставляет списки групп, предметов и тестов из базы. Для диапазона занятий требуются положительные целые числа, начало не больше конца. Ошибки ввода поясняются в стандартном потоке ошибок с ненулевым кодом завершения.

Отчёт содержит название функции, выбранные параметры и читаемый текст в стандартном потоке вывода. Отсутствие результатов, отсутствие зависимостей и недоступность или некорректный формат исходных файлов сообщаются явно. Исходная база не изменяется.
