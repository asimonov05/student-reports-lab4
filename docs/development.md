# Основные решения при разработке

## Основание работы

7 ноября 2026 года репозиторий преподавателя `dmieter/os-labs` обновлён до состояния `e52e240`. В нём найдено общее задание ЛР № 4: бригадная разработка shell-скриптов, краткая документация, отчёт о тестировании и фиксация основных моментов разработки. Репозиторий выполненной ЛР № 3 проверен и уже соответствовал своему удалённому состоянию.

Для этой работы создан отдельный проект бригады `student-reports-lab4`. Контекст ЛР № 3 используется для формата данных; индивидуальные изменения результатов из той работы не копируются. В проект включён исходный архивный набор преподавателя.

Приоритет требований: индивидуальное ТЗ и предоставленные ответы преподавателя, затем общее задание ЛР № 4 и описание форматов ЛР № 3. Исходное ТЗ сохранено в `docs/source`; рабочие трактовки собраны в [требованиях](requirements.md), отдельно от подтверждённых требований.

## Устройство решения

Командный интерфейс `bin/student-report` принимает команду и параметры. Библиотека `lib/reports.sh` проверяет исходные файлы и формирует отчёт. Вычисления используют Bash и GNU awk; Python в программе и тестовых сценариях не требуется. GNU awk выбран для группировки записей и корректного подсчёта символов в UTF-8.

Графический интерфейс `bin/student-gui` вызывает тот же командный интерфейс. Zenity отвечает за выбор параметров и показ текста, а формулы расчёта не дублируются в окнах. CLI разделяет столбцы табуляцией; GUI выравнивает их пробелами для моноширинного шрифта и печатает тот же оформленный текст в stdout. Это позволяет проверять результаты без графической сессии и сохраняет одинаковые вычисления для обоих способов запуска.

Списки групп, предметов и тестов строятся из файлов базы. Путь к базе задаётся через `--data`, поэтому программа может работать с поставляемыми данными и отдельными учебными примерами. Операции чтения не переписывают исходные файлы.

## Существенные решения

Ключ студента включает полную группу и исходный идентификатор. Это предотвращает объединение однофамильцев из разных лет и групп. В выводе сохраняются исходные имена: восстановить полные ФИО из доступных данных нельзя.

В базе встречаются оценки с суффиксами и даты, не соответствующие порядку попыток. Поэтому порог успешности проверяется по числовой части оценки, а сдача с первой попытки — по единственной успешной записи в каждом тесте. Год в годовом отчёте, напротив, берётся именно из даты. Эти правила отражены в отдельных тестовых сценариях.

При равных максимумах посещаемости, длины фамилии и годового результата выводятся все победители. Для пересдач выводится один победитель в стабильном порядке. Годовой отчёт устраняет повтор одного студента из нескольких одинаково лучших попыток.

## Проверка и передача

Проверка разделена на сценарии вычислений с небольшой контролируемой базой и сценарии переходов графического интерфейса. В Linux пройдены 62 проверки вычислений и 13 проверок диалогов; результаты всех пяти функций на исходной базе сверены с отдельно рассчитанными эталонами. Проверено побайтовое соответствие 119 файлов базы оригинальному архиву. Условия, фактические результаты и пределы проверки записаны в [отчёте о тестировании](testing.md).

Для дальнейших изменений добавлен `.github/workflows/test.yml`: проверка синтаксиса Bash, ShellCheck, тесты вычислений, тесты диалогов и запуск всех функций на исходной базе. [Первый запуск в GitHub](https://github.com/asimonov05/student-reports-lab4/actions/runs/42301379687) для коммита `7affa26` успешно завершился.

Состав бригады и распределение ролей не выдумываются. В приложенном ТЗ отчёт о тестировании назначен Сергею Г.; технический отчёт в репозитории служит материалом для его проверки и оформления. Преподавателю сообщения автоматически не отправляются.
