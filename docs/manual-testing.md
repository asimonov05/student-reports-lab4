# Ручное тестирование через терминал (CLI)

Без окон и автотестов. Вводишь команду, сравниваешь ответ с ожидаемым, делаешь скриншот терминала. Проверяется программа `bin/student-report`.

Для последовательной проверки без перебора похожих значений используй [чек-лист CLI по веткам и границам](manual-testing-full.md): в нём собраны разные ветки расчётов, отказы валидаторов, права доступа и потоки вывода.

## 1. Подготовка

Открой терминал **в папке проекта**: в ней должны находиться `bin`, `tests`, `data` и `README.md`. Проверить можно командой `ls`.

Нужны Bash 4+ и gawk. Если gawk не установлен, в Ubuntu/Debian:

```bash
sudo apt update
sudo apt install gawk
```

Запусти Bash:

```bash
bash
```

Дальше работай в этом же терминале. Не закрывай его между проверками: в нём сохраняются пути к тестовой базе. Не включай `set -e`: программа будет намеренно выдавать ошибки в отрицательных тестах.

Сделай первый скрин — версия проекта и окружение:

```bash
git rev-parse --short HEAD
bash --version | head -n 1
gawk --version | head -n 1
locale charmap
```

Теперь подготовь маленькую учебную базу, чтобы результаты можно было проверить вручную:

```bash
TEST_DIR=$(mktemp -d)
BASE="$TEST_DIR/data with spaces"
bash tests/make-fixture.sh "$BASE"
```

Это **только создание данных**, не запуск автотестов. Настоящая база проекта не меняется. В тестовой базе две группы, два предмета и по четыре теста. Путь с пробелами выбран специально: программа должна работать и с ним.

### Как делать скриншоты

- Выполняй команды по одной. На скрине должны читаться команда и её результат.
- Сразу после проверяемой команды вводи:

  ```bash
  echo "Код: $?"
  ```

  `0` — успешная работа, `2` — предусмотренная ошибка ввода или данных. Не вводи другую команду перед `echo`, иначе проверишь её код, а не код программы.
- Назови скрины по номерам проверок: `01.png`, `02.png` и т. д. Несколько коротких проверок можно показать на одном скрине.
- Если результат не совпал, запиши это как ошибку программы. Не меняй ожидаемый ответ под фактический.

## 2. Основные проверки — все пять функций

### 01. Какие параметры доступны

```bash
./bin/student-report --data "$BASE" groups
./bin/student-report --data "$BASE" subjects
./bin/student-report --data "$BASE" tests 'Математика'
```

Выполняй отдельно, после каждой команды проверяй код.

**Ожидается:** группы `A-06-23`, `A-09-22`; предметы `История`, `Математика`; номера тестов `1`, `2`, `3`, `4`. Коды `0`.

### 02. Посещаемость

Сначала покажи исходные отметки:

```bash
cat "$BASE/Математика/A-06-23-attendance"
```

Получится:

```text
PetrovAB 1110
IvanovCD 0111
Surovtsev-ButovA 1101
АлександровскаяАБ 0111
MixupGH 0000
```

`1` означает присутствие, `0` — пропуск. Считаем занятия со второго по четвёртое, включая обе границы:

```bash
./bin/student-report --data "$BASE" attendance A-06-23 'Математика' 2 4
echo "Код: $?"
```

**Ожидается:** только `IvanovCD` и `АлександровскаяАБ`, у каждого **3 посещения**, код `0`.

Так проверяем и подсчёт, и вывод нескольких победителей при равенстве.

### 03. Пересдачи

```bash
./bin/student-report --data "$BASE" retakes A-06-23 'Математика' 1
echo "Код: $?"
```

**Ожидается:** один `MixupGH`, группа `A-06-23`, **2 пересдачи**, код `0`.

Для проверки вручную можно посмотреть файл:

```bash
cat "$BASE/Математика/tests/TEST-1"
```

У MixupGH три попытки, значит, две пересдачи: первая попытка пересдачей не считается. У Surovtsev-ButovA столько же попыток, в том числе за разные годы. По принятому правилу при равенстве выводится один студент, текущая программа выбирает MixupGH.

### 04. Все тесты с первой попытки

```bash
./bin/student-report --data "$BASE" first-pass 'Математика'
echo "Код: $?"
```

**Ожидается ровно четыре студента**, код `0`:

```text
AbcdefghijklmnoAB  A-09-22
IvanovCD          A-06-23
PetrovAB          A-09-22
АлександровскаяАБ  A-06-23
```

Почему это хорошая выборка:

- PetrovAB из `A-06-23` исключён из-за пересдачи, а одноимённый из `A-09-22` включён. Разные группы нельзя объединять.
- OtherIJ исключён: у него нет попытки четвёртого теста.
- IvanovCD включён: оценки `3--` и `3++` считаются положительными.

### 05. Самые длинные фамилии

```bash
./bin/student-report --data "$BASE" longest-names
echo "Код: $?"
```

**Ожидается**, код `0`:

| Студент | Группа | Фамилия | Длина |
| --- | --- | --- | --- |
| AbcdefghijklmnoAB | A-09-22 | Abcdefghijklmno | 15 |
| Surovtsev-ButovA | A-06-23 | Surovtsev-Butov | 15 |
| АлександровскаяАБ | A-06-23 | Александровская | 15 |

Проверяется, что инициалы не входят в длину, дефис входит, кириллица считается в символах, а не в байтах. Должны выводиться все три победителя из разных групп.

### 06. Лучшие результаты по годам

```bash
./bin/student-report --data "$BASE" yearly-best 'Математика' 1
echo "Код: $?"
```

**Ожидается ровно четыре строки студентов**, код `0`:

| Год | Студент | Группа | Правильных ответов |
| --- | --- | --- | --- |
| 2024 | IvanovCD | A-06-23 | 25 |
| 2024 | АлександровскаяАБ | A-06-23 | 25 |
| 2025 | AbcdefghijklmnoAB | A-09-22 | 24 |
| 2025 | OtherIJ | A-09-22 | 24 |

Проверяем, что годы не смешиваются и выводятся все равные максимумы. Ответы разных попыток не складываются: у PetrovAB/A-06-23 есть 14 и 16 ответов, но результат 30 появляться не должен. Для сравнения используется число ответов, а не оценка.

## 3. Краевые случаи без изменения данных

Каждая строка таблицы — отдельная команда. После неё вводи `echo "Код: $?"` и сравнивай результат. Порядок студентов в таблицах ниже не важен, состав и числа — важны.

### 07. Границы диапазона, другая группа, нулевые пересдачи

| Команда | Ожидается, код 0 |
| --- | --- |
| `./bin/student-report --data "$BASE" attendance A-06-23 'Математика' 1 1` | PetrovAB и Surovtsev-ButovA, по 1 |
| `./bin/student-report --data "$BASE" attendance A-06-23 'Математика' 4 4` | IvanovCD, Surovtsev-ButovA, АлександровскаяАБ, по 1 |
| `./bin/student-report --data "$BASE" attendance A-06-23 'Математика' 1 4` | IvanovCD, PetrovAB, Surovtsev-ButovA, АлександровскаяАБ, по 3 |
| `./bin/student-report --data "$BASE" attendance A-09-22 'Математика' 1 4` | Только PetrovAB из A-09-22, 4 |
| `./bin/student-report --data "$BASE" retakes A-09-22 'Математика' 1` | Только AbcdefghijklmnoAB, 0 пересдач |

### 08. Другой предмет и номер теста

```bash
./bin/student-report --data "$BASE" retakes A-06-23 'История' 1
```

**Ожидается:** IvanovCD, 1 пересдача, код `0`. Это не результат теста 1 по математике — предмет должен учитываться.

```bash
./bin/student-report --data "$BASE" yearly-best 'Математика' 4
```

**Ожидается:** за 2024 год — MixupGH, PetrovAB, Surovtsev-ButovA, АлександровскаяАБ из A-06-23 и PetrovAB из A-09-22, у всех 20; за 2025 — AbcdefghijklmnoAB из A-09-22, 20. Код `0`. Проверяется другой номер теста и сохранение одноимённых студентов разных групп.

### 09. Неправильный диапазон

Команды ниже вводи по одной. После каждой проверяй код:

```bash
./bin/student-report --data "$BASE" attendance A-06-23 'Математика' 0 2
./bin/student-report --data "$BASE" attendance A-06-23 'Математика' -1 2
./bin/student-report --data "$BASE" attendance A-06-23 'Математика' 1.5 2
./bin/student-report --data "$BASE" attendance A-06-23 'Математика' abc 2
./bin/student-report --data "$BASE" attendance A-06-23 'Математика' '' 2
./bin/student-report --data "$BASE" attendance A-06-23 'Математика' 3 2
./bin/student-report --data "$BASE" attendance A-06-23 'Математика' 1 5
./bin/student-report --data "$BASE" attendance A-06-23 'Математика' 1 0
./bin/student-report --data "$BASE" attendance A-06-23 'Математика' 1 1000000000
```

**Везде ожидается код `2` и понятное сообщение об ошибке**, без успешного отчёта.

Проверены: ноль, отрицательное число, дробь, текст, пустое поле, обратный диапазон, выход за четыре занятия и слишком большое число. Пустое поле в терминале передаётся как `''`; если просто пропустить аргумент, это уже другая проверка.

После ошибок повтори команду из проверки 02: правильные параметры должны снова дать правильный результат.

### 10. Неизвестные параметры, пропущенный аргумент, справка

Выполняй отдельно, проверяя код после каждой команды:

```bash
./bin/student-report --data "$BASE" attendance UNKNOWN 'Математика' 1 2
./bin/student-report --data "$BASE" yearly-best 'НетПредмета' 1
./bin/student-report --data "$BASE" retakes A-06-23 'Математика' 0
./bin/student-report --data "$BASE" retakes A-06-23 'Математика' 5
./bin/student-report --data "$BASE" attendance A-06-23 'Математика' 1
./bin/student-report --data "$BASE" longest-names extra
./bin/student-report unknown-command
./bin/student-report --data "$TEST_DIR/no-database" groups
```

**Ожидается:** объяснение ошибки, код `2`. Проверяются неизвестные группа/предмет/команда, номера теста вне 1–4, нехватка и избыток аргументов, отсутствующая база.

```bash
./bin/student-report --help
echo "Код: $?"
```

Здесь ожидается справка, код `0`.

## 4. Особые случаи на отдельной копии

Эти проверки чуть длиннее, но тоже выполняются простым копированием команд. Изменять файлы в папке `data` не нужно.

### 11. Ни у кого нет посещений

```bash
BROKEN="$TEST_DIR/changed-data"
bash tests/make-fixture.sh "$BROKEN"
printf '%s\n' 'PetrovAB 0000' 'IvanovCD 0000' 'Surovtsev-ButovA 0000' 'АлександровскаяАБ 0000' 'MixupGH 0000' > "$BROKEN/Математика/A-06-23-attendance"
./bin/student-report --data "$BROKEN" attendance A-06-23 'Математика' 1 4
echo "Код: $?"
```

**Ожидается:** все пять студентов группы, у каждого 0 посещений, код `0`. Нулевой максимум — тоже результат.

### 12. Пустой тест и отсутствие сдавших

Первая команда заново создаёт чистую копию:

```bash
bash tests/make-fixture.sh "$BROKEN"
printf '' > "$BROKEN/Математика/tests/TEST-1"
./bin/student-report --data "$BROKEN" yearly-best 'Математика' 1
echo "Код: $?"
```

**Ожидается:** `Подходящих студентов нет.`, код `0`, не ошибка программы.

```bash
./bin/student-report --data "$BROKEN" first-pass 'Математика'
echo "Код: $?"
```

**Ожидается:** то же сообщение и код `0`: никто не сдавал первый тест, значит, никто не сдал все четыре.

### 13. Повторный лучший результат одного студента

```bash
bash tests/make-fixture.sh "$BROKEN"
printf '%s\n' 'A-06-23;IvanovCD;2024-04-10;25;5' >> "$BROKEN/Математика/tests/TEST-1"
./bin/student-report --data "$BROKEN" yearly-best 'Математика' 1
echo "Код: $?"
```

**Ожидается:** тот же результат из проверки 06, код `0`. IvanovCD за 2024 год должен быть выведен только один раз.

### 14. Повреждённая строка и невозможная дата

```bash
bash tests/make-fixture.sh "$BROKEN"
printf '%s\n' 'A-06-23;IvanovCD;2024-01-10;25' > "$BROKEN/Математика/tests/TEST-1"
./bin/student-report --data "$BROKEN" yearly-best 'Математика' 1
echo "Код: $?"
```

**Ожидается:** ошибка — в строке должно быть пять полей; здесь только четыре. Код `2`.

Теперь замени строку:

```bash
printf '%s\n' 'A-06-23;IvanovCD;2023-02-29;25;5' > "$BROKEN/Математика/tests/TEST-1"
./bin/student-report --data "$BROKEN" yearly-best 'Математика' 1
echo "Код: $?"
```

**Ожидается:** ошибка даты, код `2`: 2023 год не високосный.

```bash
printf '%s\n' 'A-06-23;IvanovCD;2024-02-29;25;5' > "$BROKEN/Математика/tests/TEST-1"
./bin/student-report --data "$BROKEN" yearly-best 'Математика' 1
echo "Код: $?"
```

**Ожидается:** один лидер за 2024 — IvanovCD/A-06-23, 25 ответов, код `0`: 29 февраля 2024 существует.

### 15. Обязательный файл отсутствует

```bash
bash tests/make-fixture.sh "$BROKEN"
mv "$BROKEN/Математика/tests/TEST-4" "$TEST_DIR/TEST-4.saved"
./bin/student-report --data "$BROKEN" first-pass 'Математика'
echo "Код: $?"
```

**Ожидается:** сообщение об отсутствующем TEST-4, код `2`. Файл не удаляется, а перемещается в другую временную папку.

## 5. Проверка на настоящих данных

Здесь `--data` не нужен: программа использует базу из репозитория. Вводи команды по одной, проверяй код и делай скрины:

```bash
./bin/student-report attendance Ae-21-23 'Цирковое_Дело' 4 10
```

**Ожидается:** GorbenkoKY, LiaminTA, NesterovAS, PershakovSA — по 7 посещений.

```bash
./bin/student-report retakes Ae-21-23 'Цирковое_Дело' 1
```

**Ожидается:** BurmistrovSF, 8 пересдач.

```bash
./bin/student-report first-pass 'Пересдачеведение'
```

**Ожидается:** 29 студентов. Одно количество не доказывает правильность всего списка; полный состав небольшой контрольной выборки уже проверяется в 04.

```bash
./bin/student-report longest-names
```

**Ожидается:** Surovtsev-ButovA, группа A-06-04, фамилия Surovtsev-Butov, 15 символов.

```bash
./bin/student-report yearly-best 'Цирковое_Дело' 1
```

**Ожидается:** результаты за 2007–2026 годы. За 2026 год — ровно пять лидеров с 25 ответами: KarpovaVG и SaponGM из A-06-23, LopatinAV из A-09-23, BurmistrovSF и LiaminTA из Ae-21-23. Если весь вывод не помещается, сделай скрины верхней и нижней части.

У всех пяти команд ожидается код `0`.

## 6. Проверка, что исходные данные не меняются

Если будешь делать эту проверку, **до команд раздела 5** скопируй в терминал:

```bash
find data/labfiles-3-26 -type f -exec sha256sum {} + | sort > "$TEST_DIR/before.txt"
```

Это сохраняет контрольные суммы файлов. После пяти команд раздела 5 выполни:

```bash
find data/labfiles-3-26 -type f -exec sha256sum {} + | sort > "$TEST_DIR/after.txt"
diff "$TEST_DIR/before.txt" "$TEST_DIR/after.txt"
echo "Код сравнения: $?"
```

**Ожидается:** `diff` ничего не печатает, код сравнения `0`. Это значит, что состав и содержимое обычных файлов базы не изменились. Если раздел 5 уже пройден, сохрани суммы «до», повтори его и сравни с суммами «после».

## 7. Что записать в отчёт

Для каждого выполненного варианта нужна строка:

| Проверка | Ожидалось | Получилось | Итог | Скрин |
| --- | --- | --- | --- | --- |
| 02. Посещаемость 2–4 | Два студента, по 3; код 0 | Заполни после своего запуска | Пройдено / ошибка | 02.png |

Если в разделе несколько вариантов, отмечай их отдельно: например, `09 — нулевое занятие`, `09 — дробное занятие`. Не пиши «пройдено» для того, что не запускал.

Этот набор покрывает все пять функций и основные краевые случаи. Проверки всех возможных повреждений файлов, прав доступа и окружений сюда намеренно не включены. В отчёте называй это **ручным функциональным тестированием CLI**, а не проверкой всей программы во всех условиях.
